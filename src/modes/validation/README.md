# `src/modes/validation`

Validation mode: an inbound `Authorization: Bearer <token>` is checked against the provider's RFC 7662 introspection endpoint and the request is forwarded or refused. The wire behaviour and the credential choice are in the root README under [Validation mode](../../../README.md#validation-mode-authmode--validation) and [Introspection client identity](../../../README.md#introspection-client-identity); revocation under [Revocation and the access-token lifetime](../../../README.md#revocation-and-the-access-token-lifetime). This file states who owns what and which test pins it. The boundary review behind it is [#95](https://github.com/o3co/auth.proxy/issues/95).

## Responsibility

| File | Kind | Owns |
| --- | --- | --- |
| [`introspection-client.mts`](introspection-client.mts) | external connection behind [`IntrospectionClient`](introspection-client.mts) | one `POST` per call and the response read as RFC 7662 — the status, the JSON, `active` being a boolean; the error contract [`IntrospectHttpError`](introspection-client.mts), the result type [`IntrospectionResult`](introspection-client.mts), the credential choice [`buildAuthHeader`](introspection-client.mts). No state. |
| [`introspection-cache.mts`](introspection-cache.mts) | interface + in-memory implementation | [`IntrospectionCache`](introspection-cache.mts) entries: served while live, swept on write, bounded at `maxEntries`. Keyed by whatever the caller keys it by. |
| [`introspect.mts`](introspect.mts) | process | what this path accepts on top of a valid response and what may be cached ([`createIntrospector`](introspect.mts)): the Bearer-only refusals, the malformed-`exp` 502, the token that expired during the call, the digest key, the bound anchored at the request. Returns the [`Introspector`](decision.mts) the decision reads. No state of its own. |
| [`decision.mts`](decision.mts) | process | the validation decision ([`decideValidation`](decision.mts)): two header values in, a [`ValidationOutcome`](decision.mts) out — `forward` or `reject` (status and the `{ code, message }` body); what it needs is [`ValidationDeps`](decision.mts), an [`Introspector`](decision.mts) and the logger. No state of its own. |
| [`router.mts`](router.mts) | assembly + transport | [`createRouter`](router.mts) builds the client, the cache and the introspector between them ([`buildIntrospector`](router.mts)) — or takes `deps.introspect` and `deps.logger` — and mounts the shared upstream stage ([`createUpstreamProxy`](../../router/upstream.mts)); [`validationMiddleware`](router.mts) reads the two headers, calls `decideValidation` and applies the outcome to `req` / `res`, throwing on an outcome kind it does not know (the `never` guard). |

The three replaceable pieces the injection path already had are here now (#95 F5): the provider's endpoint behind [`IntrospectionClient`](introspection-client.mts), the store behind [`IntrospectionCache`](introspection-cache.mts), and between them the reading of the response that decides what may be held. The cache belongs to the router that built it rather than to the module, so two routers in one process no longer share one — [`app.mts`](../../app.mts) builds a single router, and the injection path draws the same line. The decision reads an [`Introspector`](decision.mts), a function `(token, requestId) → IntrospectionResult`, which [`buildIntrospector`](router.mts) composes from the three; a caller may supply its own through `deps` (#95 F3), and then owns everything below that seam.

## Public contract

`createRouter({ config, deps? })` returns an Express router and throws unless `auth.mode` is `"validation"` (the guard at the top of [`createRouter`](router.mts)); `deps` may supply the introspector and the logger, defaulting to what it builds — pinned by [`accepts an injected introspector and logger: fetch and the singleton are not touched, and the inbound bytes are forwarded`](__tests__/router.test.mts) and [`an injected logger receives the introspect failure line`](__tests__/router.test.mts). Refusals are `{ "code", "message" }` — a different shape from injection's — with no `WWW-Authenticate`.

| Inbound | Answer | Where | Pinned by ([`router.test.mts`](__tests__/router.test.mts)) |
| --- | --- | --- | --- |
| no `Authorization` | forwarded unchanged | the first check in [`decideValidation`](decision.mts) | `passes a request without Authorization through to upstream without consulting the provider` |
| not `Bearer <token>` (scheme case-sensitive) | `400 Invalid Token Type` | `extractBearerToken` returning `null` | `answers 400 Invalid Token Type to a non-Bearer scheme without consulting the provider` |
| anything but `active: true` — `false`, including a `cnf`, a non-Bearer `token_type` or expiry during the call, and any non-boolean a supplied introspector returns | `401 Invalid Token` | the `result.active !== true` check in `decideValidation` | `refuses bound token %j before forwarding`; `forwards a live token, then refuses it when its warm cache reaches exp` |
| provider `401` | `401 Invalid Token` | `IntrospectHttpError` with status 401 in the `catch` | `answers 401 Invalid Token when the provider answers 401` |
| any other failure: non-2xx, invalid body, timeout, network | `500 Internal Server Error` | the `catch` fallthrough | `answers 500 Internal Server Error when $failure` (a provider 503, a 200 with a non-JSON body, a rejected `fetch`) |
| `active: true` | forwarded; upstream receives the inbound `Authorization` bytes | `forward`, applied as `next()` into the shared stage ([`createUpstreamProxy`](../../router/upstream.mts)) | `forwards a live token, then refuses it when its warm cache reaches exp`; the bytes: `accepts an injected introspector and logger: fetch and the singleton are not touched, and the inbound bytes are forwarded` |

**What a provider 401 means (F7).** Without client credentials the inbound token *is* the introspection credential (`Bearer <token>`, [`buildAuthHeader`](introspect.mts)), so a provider 401 is about that token and `401 Invalid Token` is right. With `CLIENT_ID` / `CLIENT_SECRET` the credential is the proxy's own `client_secret_basic`, and a provider 401 means the proxy's client authentication was refused (RFC 7662 §2.3) — a configuration error, answered today as the same `401 Invalid Token`, indistinguishable on the wire. Injection mode tells the two apart (`provider_config_error` 502). #95 flags this as a separate decision; nothing has changed yet.

## Inputs and outputs

- In: `Authorization`, read by [`extractBearerToken`](../../express/bearer.mts) — case-sensitive `Bearer`, then the first SP-delimited word; `x-request-id` as normalised by [`express/requestId.mts`](../../express/README.md).
- Out, provider: `POST auth.validation.introspect.url`, form body `token=<token>`, `Authorization` either Basic (both client credentials set) or `Bearer <token>`, `x-request-id`, `AbortSignal.timeout(timeoutMs)` (the `fetch` call in [`introspect`](introspect.mts)).
- Out, upstream: the inbound request with every inbound header — `express-http-proxy` copies `req.headers` wholesale except `connection` and `host`, cookies included (`reqHeaders` in its `lib/requestOptions.js`); this middleware modifies nothing, and the shared stage's decorator only re-sets casing ([`createUpstreamProxy`](../../router/upstream.mts)). **The forwarded header is the inbound bytes unchanged, while the introspected token is the first SP-delimited word** (F14): `Bearer abc123 extra` introspects `abc123` and forwards `Bearer abc123 extra`. The extraction half is pinned by [`keeps only the first token when the header carries trailing content`](../../express/__tests__/bearer.test.mts) and [`forwards an active token, handing the introspector the first SP-delimited word and the request id`](__tests__/decision.test.mts); the forwarding half by [`accepts an injected introspector and logger: fetch and the singleton are not touched, and the inbound bytes are forwarded`](__tests__/router.test.mts). The upstream must verify the token it is handed regardless ([Inbound Authorization headers](../../../README.md#inbound-authorization-headers)).

## Dependencies

`router` → `decision`, [`express/requestId`](../../express/requestId.mts), [`router/upstream`](../../router/upstream.mts), the [`logger`](../../logger.mts) singleton (as the default `deps.logger`), `introspect` (`introspect`, `buildAuthHeader`), the config types · `decision` → [`express/bearer`](../../express/bearer.mts), `introspect` (`IntrospectHttpError` and the result type) and the [`Logger`](../../logger.mts) type · `introspect` → [`oauth/client-secret-basic`](../../oauth/client-secret-basic.mts). No cycles. The upstream proxy stage is [`createUpstreamProxy`](../../router/upstream.mts) (`src/router/upstream.mts`), shared with injection (F18, #97).

## Invariants

1. **Parsed once.** `Authorization` is parsed once, by [`extractBearerToken`](../../express/bearer.mts) at the top of [`decideValidation`](decision.mts), and every later step reads `bearer.token`. What is forwarded is decided by `req.headers`, which the middleware never modifies on this path: the library copies every inbound header and the shared stage's decorator only re-sets casing — see the docstring on [`createUpstreamProxy`](../../router/upstream.mts), which also notes that dropping the decorator is tracked with F14 / F15 on #95. `BearerToken.raw` is unused anywhere today (F15).
2. **Cache key and bound.** Key = SHA-256 of the token (`cacheKey` in [`introspect.mts`](introspect.mts)). An entry expires at `min(now + cacheTtlSec, exp)` with `now` captured before the call, so entries are capped at `exp` and anchored at the request. Pinned by [`returns the cached result on a second call within the TTL, calling the provider once`](__tests__/introspect.test.mts), [`keys the entry by the digest of the token, never the token`](__tests__/introspect.test.mts), [`anchors the bound at the request, not at the response`](__tests__/introspect.test.mts), [`stops serving a warm entry at the token's exp`](__tests__/introspect.test.mts) and, through the router, [`forwards a live token, then refuses it when its warm cache reaches exp`](__tests__/router.test.mts). `cacheTtlSec` ≤ 0 disables both sides — [`neither reads nor writes the cache when caching is disabled`](__tests__/introspect.test.mts).
3. **What is never cached:** a response carrying `cnf` or a non-Bearer `token_type` (answered `active: false`), a token that expired during the call, an entry already past its bound on arrival, and every error — each returns or throws before the single `cache.set` in [`createIntrospector`](introspect.mts). Pinned by [`refuses a positive response that expired during the provider call, and caches nothing`](__tests__/introspect.test.mts), [`refuses unsupported possession evidence on the Bearer path: %j`](__tests__/introspect.test.mts) (which asserts the empty cache), [`refuses bound token %j before forwarding`](__tests__/router.test.mts); the error case is documented, not tested.
4. **What is cached:** the validated response as returned, whether `active` is `true` or `false` — a plain `active: false` from the provider is a statement about the token and is held for the same bound, pinned by [`caches a plain active: false, which is the provider's answer about the token`](__tests__/introspect.test.mts). The refusals this path makes itself are not: they are not the provider's answer.
5. **Only a boolean `active` is trusted** (the RFC 7662 §2.2 check in [`createIntrospectionClient`](introspection-client.mts)); `{"active":"false"}` is a 502, not a bypass. Pinned by [`throws IntrospectHttpError(502) when active is not a boolean — %s`](__tests__/introspection-client.test.mts), [`throws IntrospectHttpError(502) when 200 body is valid JSON but not a plain object — %s`](__tests__/introspection-client.test.mts). The decision applies the same rule again on the value it is handed, since a supplied introspector owns that check (below).
6. **Eviction:** expired entries are swept, then the oldest insertion is dropped at `maxEntries` — both inside [`createIntrospectionCache`](introspection-cache.mts), which is the only thing that knows the bound. Pinned by [`sweeps expired entries on the next write, so a stale one does not hold a slot`](__tests__/introspection-cache.test.mts), [`drops the oldest insertion at the bound`](__tests__/introspection-cache.test.mts) and, through the composition, [`evicts the oldest entry at maxEntries, so the evicted token is fetched again`](__tests__/introspect.test.mts).
7. **No single-flight (F6).** There is no pending table, so concurrent misses on one token each call the provider — unlike the session and exchange paths, which coalesce. Adding it is a behaviour change and a separate decision. Documented, not tested.

## Failure and lifecycle

- [`IntrospectHttpError`](introspection-client.mts) carries the provider's status for a non-2xx and `502` for a 200 whose body is not a valid RFC 7662 response. A rejected `fetch` — timeout or network — propagates unwrapped ([`propagates fetch rejection (network error / AbortError)`](__tests__/introspection-client.test.mts)); the decision logs `introspect failed` with the error under `x-request-id` and answers 500 — the provider's own 401 is the one status mapped to `401 Invalid Token` ([`answers 500 Internal Server Error when $failure`](__tests__/router.test.mts), [`answers 401 Invalid Token when the provider answers 401, logging the failure with the request id`](__tests__/decision.test.mts)).
- **A supplied introspector owns what `introspect` guarantees:** the RFC 7662 boolean `active` check — the decision forwards on `true` alone, so a non-boolean is `401 Invalid Token`, never a bypass ([`answers 401 Invalid Token when a supplied introspector resolves a non-boolean active (%j), never forwarding on truthiness`](__tests__/decision.test.mts)) — the `cnf` / `token_type` / expiry refusals, and its own timeout; the decision applies none of them. What `createRouter` builds is the bundled implementation of exactly that contract, and a caller replacing it replaces the client, the cache and the reading between them together — [`does not build either when the caller supplies its own introspector`](__tests__/build-introspector.test.mts).
- **Cancellation is the timeout only:** neither [`IntrospectionClient`](introspection-client.mts) nor [`Introspector`](decision.mts) accepts a signal; a caller's disconnect does not abort the provider call. Documented, not tested (F10).
- **Lifetime (F21):** the cache is created by [`createRouter`](router.mts) and lives in its closure until process exit — one per router, pinned by [`gives each router its own cache, so one router's entries are not another's`](__tests__/build-introspector.test.mts); [`app.mts`](../../app.mts) builds one router and passes no `cleanup`, so a drain does not wipe it. [`IntrospectionCache.clear()`](introspection-cache.mts) is unreachable from outside for a router-built instance; a caller that supplies `deps.introspect` owns whatever it built. Nothing needs releasing.
- `cacheMaxEntries` and `timeoutMs` no longer carry a third declaration: the parameter defaults went with the fused function (F23), and the schema is the only place they are declared — see [`config/README.md`](../../../config/README.md).
